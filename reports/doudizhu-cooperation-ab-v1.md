# 斗地主协作失败：显式控制事实对照实验

> 术语更新：本文保留历史实验叙述。其中“失败/修复”指策略与参考建议的差异，不是软件测试失败，也不表示 JEV 必须最优。新规范见 [策略评测](../docs/strategy-evaluation.md)。

本轮没有修复抢队友牌权问题。原始状态与增加控制事实的状态均为 **9/24** 次标注匹配，48 次决策全部成功返回、没有强制动作。

原始记录见 [完整 JSON 报告](doudizhu-cooperation-ab-v1.json)。首次十例结果保留在 [首次报告](doudizhu-first-run.md)。

## 实验方法

- 固定请求与实际返回模型版本：`jev-1.13.0`。
- 8 个人工协作场景，每组每例重复 3 次；场景和组别先后顺序用种子 2026 打乱。
- 两组使用完全相同的四个 Noul 战术问题和最终 Choice 问题。
- 唯一干预是加入从公开信息确定的 `belief.facts.control`；不加入真实底牌、人工答案或强制过牌规则。
- 96 次 API 请求；input tokens 152,479，output tokens 5,220。

## 分场景结果

| 场景 | 原始状态 | 增加控制事实 |
| --- | --- | --- |
| 避免抢队友牌权 | 0/3 | 0/3 |
| 有威胁时必须接管队友牌权 | 3/3 | 3/3 |
| 换点数后仍应保留队友牌权 | 0/3 | 0/3 |
| 有大王也不必抢队友牌权 | 0/3 | 0/3 |
| 地主已过牌，下家可以还权队友 | 0/3 | 0/3 |
| 未知大牌仍可能存在，但地主本轮已过 | 0/3 | 0/3 |
| 队友牌安全但自己能立即走完 | 3/3 | 3/3 |
| 地主报双可能接对子走完，王炸接管 | 3/3 | 3/3 |

## 原失败场景的变化

在 `yield_to_teammate` 中，原始状态的 `must_block` 为 0.53–0.56，增加事实后为 0.33–0.34；但两组全部仍选择 A。也就是说，威胁判断的数值下降没有转化为让牌行为。此数值不是胜率，也不能据此断言模型的内部推理。

五个应让牌的场景两组都未匹配标注；需要接管以拦截地主、自己直接出完、用王炸阻止地主接对子这三类均匹配。参考底牌的穷举诊断也与这些结果一致，但它知道所有底牌，不能替代隐藏信息下的最优策略评估。

## 结论与下一步

本次证据不支持“把安全牌权显式写进状态就能修复协作”。因此保留该能力作为可选实验字段，没有把它宣称为改进后的默认策略。

接下来应测试动作级的短程后果：过牌后谁获得自由领出、接管后还剩几手散牌、控制牌耗尽后谁能抢回，以及队友的出完机会。代码负责确定转移与公开可证明的事实，JEV 对依赖隐藏牌的判断保留不确定性。可考虑候选动作展开与隐藏牌采样，而非只继续堆叠战术口诀。

这组场景专门围绕已知失败构造，含点数变体，重复调用也不是独立样本。9/24 不能与首次十例的 9/10 直接比较，二者都不是实战胜率。
