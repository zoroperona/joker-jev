# 每步重新决策的完整残局

本版从一个固定小残局开始，运行到自然终局；不是从 54 张牌发牌开始的完整斗地主。

```bash
# 本地纯模拟，默认 2 个新快照 × 3 个目标座位 × 2 种风格 = 12 局
python3 -m joker_jev.games.doudizhu.fullgame --output reports/full-local-new.json

# 三种方法：共 36 局；固定模型 jev-1.13.0
python3 -m joker_jev.games.doudizhu.fullgame --live --cases 2 --workers 3 --output reports/full-live-new.json
```

可设置 `--seed`、`--repeats`、`--model` 和 `--env-file`。输出路径及相邻的 `*-episodes` 目录必须是新路径。默认三个线程处理相互独立的对局，每局拥有独立后端和策略随机源，不共享 JEV 会话或记忆。

## 同一对局引擎

`EndgameGame` 继承 `CardGame[Position]`，使用通用 `core.engine.play`：统一校验动作、推进状态、累计团队奖励和公开事件。此前比牌游戏仍使用同一引擎。

`ReplanningAgent` 在目标座位的每一轮重新构造视角并决策：

- `current_jev`：当前战术问题加 Choice。
- `simulation`：从最新可见状态重新枚举兼容牌分配并模拟。
- `simulation_jev`：JEV 读取本轮新计算的模拟分析后选牌。

仅有一个合法动作时直接执行；它仍记作一次决策，但不会调用模型或搜索。各方法不能因人工建议不同而被判失败。

## 座位与搭档

每副固定牌分配都让目标策略依次占据地主、地主下家、地主上家。牌不跟着策略移动，因此同一座位上的不同方法拿到完全相同的牌和起始局面。

- 目标是农民：地主使用 `pressure`，另一农民分别用 `cooperative` 或 `greedy`。
- 目标是地主：两位农民分别共同使用 `cooperative` 或 `greedy`。

只有目标座位由被测方法控制，且控制其全程；队友不会因目标方法变化而一起换成 JEV。目标是地主时“农民风格”指对手组合，目标是农民时指队友，报告分别按座位与风格分组，不混淆这两种含义。

## 新案例与信息隔离

`heldout.py` 使用固定种子随机生成快照，不附带人工动作偏好，也不调用全知求解器筛选。每人三张；整个剩余牌池普通点数至多两张、王各一张，仍限定单牌/对子/王炸。

在任何 API 调用前，主报告写入包含所有底牌的研究用 manifest 和 SHA-256。策略没有权限读取 manifest，只拿到当前玩家的决策上下文。该“新案例”指未用于此前提示与策略调试；一旦本轮结果被查看，就应视为开发数据，不能长期宣称独立留出集。小规模人工子域也不代表真实发牌分布。

每一步的公开出牌更新已出牌计数、剩余张数与未知牌池。观察包含从当前快照开始的完整公开事件顺序；没有虚构之前的出牌历史。猜牌概率随牌数重算，但仍假设未知实体牌均匀分配，不根据行为推断“对方过牌所以没有大牌”。

每个玩家只看到自己的手牌。逐局研究日志会保存各玩家在各自回合的私有视角，方便审计；这些多视角日志不会回灌给下一位 Agent。对外公开回放应只使用其中的 `public_history`。

## 记录与指标

每局独立 JSON 在决策前、每次 API 调用前后、动作执行后更新，包含：

- 每步真实送入策略的可见状态、合法动作、公开历史、更新后的记牌推断。
- 本轮候选动作模拟估值（适用时）、模型概率、最终动作、实际公开事件和奖励。
- 每次 API 尝试的状态、真实模型版本、已知 token 用量和耗时。两阶段中第二次失败时，第一次已知用量仍保留。
- 自然终局胜负与所有玩家奖励。农民共享奖励，不因谁先走而不同。

`api_error` 与 `turn_limit` 保留未完成对局，团队收益为 null，不作为输局或平局。非法动作等实现错误保存诊断后抛出，不能被吞掉为普通策略表现。失败请求的实际账单用量可能未知。

主报告含全部尝试的完成率、按目标座位和农民风格分组的胜负、平均团队奖励、耗时与调用量。另外单独列三种方法均完成的匹配设置，避免对不同的有效样本集合直接比较。还要检查目标玩家有多少非强制决策：有些牌局主要由其他玩家决定，不能把这类胜负都解释为目标方法的能力。

默认只有两副新快照，36 局也不是 36 份独立发牌。结论仅针对这组牌、座位和简单基线，不代表完整斗地主实力或统计显著性。

## 50 副扩展协议（v2）

```bash
python3 -m joker_jev.games.doudizhu.fullgame --balanced --cases 50 --seed 20261013 --output reports/doudizhu-expanded-local-v2.json
python3 -m joker_jev.games.doudizhu.fullgame --balanced --cases 50 --seed 20261013 --live --output reports/doudizhu-expanded-live-v2.json
```

`--balanced` 在看结果前按 `(案例序号 × 3 + 座位序号) % 4` 分配风格：random、pressure、conservative、cooperative。每副牌测试全部三个目标座位，每个座位一个风格，共 150 个设置、450 局线上三策略对照。非目标座位都采用该设置风格；目标农民的风格同时描述地主对手和农民队友。风格与牌局没有全交叉，所以风格间原始胜率不能解释为风格的因果效果。

random 在合法动作间均匀随机；pressure 跟牌时优先大牌；conservative 优先不拆对子、选择较小牌，队友掌权时让牌；cooperative 使用原有公开信息协作启发式。后三者都优先直接出完手牌。它们均非最优策略，且仅访问玩家自身视角。内部模拟仍使用原有 cooperative/greedy 续局策略，没有按本轮结果调参。

manifest 和完整 settings 在任何线上调用前写入报告。设置随机种子由实验种子、案例、座位、双方风格和重复编号的 SHA-256 派生，不依赖策略数量、调度顺序或线上/本地模式。本地与线上报告应比较 manifest 哈希和 settings 完全一致；旧 v1 的派生方法不保证跨模式一致。失败局保留，不自动补跑或替换牌局。

本轮仍是每人三张的受限残局。50 副牌中的三个座位互有关联，不能把 450 局当成 450 个独立牌局；结果查看后即成为开发数据。战术行为统计仅描述已访问局面，不能当作战术正确率。

## 混合残局集合

`--scenario-set mixed` 使用 `doudizhu_mixed_v1` 生成器，按顺序循环五个结构层：手牌不均且自由领出、跟单牌、跟对子、地主剩一张、地主剩两张。50 副时每层 10 副；行动座位轮换，跟牌包含零次或一次连续过牌。手牌均为 1–4 张，当前桌面牌计入已出牌且与剩余手牌不超过实体牌总量。

这些是当前时刻的合法合成快照，不宣称由完整 54 张对局产生。不按能否压过、胜负或人工建议筛选；无法响应的强制过牌也是合法样本。`scenario_kind` 仅用于研究报告，不输入 Agent。新增集合仍遵循相同的隐藏手牌隔离和共享奖励协议。
