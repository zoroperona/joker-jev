# 游戏接入规范

每款游戏放在 `joker_jev/games/<game_id>/`，不要把该游戏的规则分支写入通用引擎。共享的是协议和流程，游戏状态类型由各游戏自行定义。

## 必须提供的内容

| 内容 | 实现位置 | 要求 |
| --- | --- | --- |
| 游戏规则 | `CardGame.rules` 和游戏 README | 稳定 game_id、规则版本、玩家及座位、牌堆、发牌、阶段、行动顺序、合法动作、胜负、终止条件 |
| 奖励定义 | `GameRules.rewards` | 写明触发条件、接收方、数值和意义，与 step 实际发放一致；说明终局是否额外结算 |
| 完整状态 | 游戏自己的状态类 | 包含环境所需信息，建议不可变；不得直接交给 Agent |
| 初始状态 | `initial_state(seed)` | 使用局部随机源，给定种子可复现；随机种子不可写入玩家观察 |
| 行动玩家 | `current_player(state)` | 从规则声明的玩家中选取；强制过牌也应提供显式动作 |
| 玩家视角 | `view(state, player_id)` | 私有区域只含自己的可见信息，公共区域只含全体可见信息；公开牌堆构成可以展示，洗牌顺序不可以 |
| 合法动作 | `legal_actions(state)` | 非终局必须非空，同一决策中 ID 唯一，payload 可 JSON 序列化；不要依靠对手底牌筛选动作 |
| 状态转移 | `step(state, action)` | 验证动作，返回新状态、公开事件和所有玩家本步增量奖励；无奖励填 0 |
| 结束判断 | `is_terminal(state)` | 明确自然终局和规则内平局；引擎步数上限属于运行失败，不是正常终局 |
| 记牌与猜牌 | `create_inference()` 返回 `CardInference` 子类 | 只使用 Observation；输出已知事实、估计和假设；未实现概率推断也须显式说明，不能虚构结果 |
| 基线策略 | `agent.py` 或通用随机策略 | 提供可运行对手，注明策略局限 |
| 验证 | `tests/` | 规则边界、非法动作、牌守恒、奖惩、终局、隐藏信息、可复现性 |

数据协议中的字典和值必须可 JSON 序列化，奖励为有限数值。卡牌可用稳定字符串 ID 表示；重复牌需要区分牌种与实体，不要直接沿用示例中的集合减法计数。

## 开发步骤

1. 新建独立目录和 `__init__.py`，先在 README 明确规则与信息可见性。
2. 继承 `CardGame[YourState]` 实现所有抽象方法，继承 `CardInference` 实现记牌推断。参考 `high_card`。
3. 在 `joker_jev/games/__init__.py` 的 `GAME_REGISTRY` 注册无参工厂。需要规则变体时可用工厂封装配置，并在规则版本中说明。
4. 补齐测试，使用通用随机 Agent 跑完整对局，再接游戏基线和 JEV。

## 信息与奖励边界

`PublicEvent` 永远是全体可见的日志，不能放发给某个人的私有手牌；新的私有信息通过该玩家下次 `view` 展示。推断器每次收到截至当前的完整公开历史，每个玩家每局使用独立推断器。

引擎使用游戏定义的原始动作，Agent 只选择 ID。非法输出直接报错，不静默替换成随机出牌，也不擅自增加规则外惩罚。需要游戏内罚分的行为，必须先被定义为游戏允许的动作或明确的规则事件。

`Transition.rewards` 为增量，不是当前比分。终局奖励在最后一次 `step` 发放，引擎不会再次结算。只在终局奖励、逐轮奖励、筹码盈亏均可表达；团队游戏应在规则中明确团队与玩家奖励的关系。不同游戏奖励尺度不同，不能直接横向比较累计奖励。

引擎不知道某个字段是不是底牌，因此视角和事件的正确性由游戏实现及其测试保证。建议构造两个只有对手底牌不同的状态，验证玩家视角与可选动作相同，且推断结果不随真实隐藏牌变化。
