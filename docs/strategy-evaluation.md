# 策略评测与正确性测试

JEV、人工经验和有限模拟都不保证最优。策略没有遵循参考建议，不构成软件测试失败。

| 类别 | 判断内容 | 处理 |
| --- | --- | --- |
| 正确性测试 | 规则、行动顺序、合法动作、终局奖励、隐藏信息隔离、API 协议 | 实现违反明确约束时测试失败 |
| 策略评测 | 特定场景和续局策略下的团队收益、调用耗时、用量和动作稳定性 | 记录结果与假设，不设通过门槛 |
| 场景诊断 | 人工偏好一致性、参考底牌的全知解 | 只说明差异，不能认定模型必须服从 |

新报告将历史的 `rubric_match` 命名为 `human_reference_agreement`，表示与人工建议一致。历史原始 JSON 保留原字段，不回写实验记录。参考建议与全知求解不一致也不会阻止实验；参考动作本身若不合法，仍属于场景数据错误。

## 三组首步对照

入口：`python3 -m joker_jev.games.doudizhu.benchmark`。默认仅运行本地模拟，`--live` 运行三组，默认模型固定为 `jev-1.13.0`。使用新的 `--output` 路径，程序逐次保存，拒绝覆盖既有记录。

1. **current_jev**：原先的四个 Noul 战术判断，再用 Choice 选动作。
2. **simulation**：对每个合法动作，在相同隐藏牌分配上模拟；优先最大化最差续局策略下的奖励下界，再比较均值，平局优先立即结束。
3. **simulation_jev**：将相同模拟得到的动作后果和策略依赖的收益汇总交给 JEV，由一个 Choice 选择。允许 JEV 不采用模拟排名第一的动作，其置信度不当作奖励权重。

当前混合组是“JEV 读取模拟分析后选牌”，尚未实现 JEV 学习对手出牌概率或评估截断叶子。混合组与当前组的问题结构也不同，因此它们的差异不能被单独归因于增加了模拟数据。

## 隐藏信息与模拟

决策器只接收 `player_state`。由自己的手牌、公开牌数和未知牌池枚举全部兼容分配；相同点数的实体牌组合合并但保留权重。没有把人工场景的真实底牌传入规划器。

每个后续行动由 `policy_action(view, policy, rng)` 决定，其输入仅为该行动玩家自己的手牌与公开信息。它不接收完整 Position，不调用 minimax，不会在不同隐藏世界中读取全知最优走法。相同观察与相同随机源必须得到相同动作。

此处只涵盖每人最多四张牌的子域，默认最多模拟 36 步，通常可以到达终局。超限记录 `truncated_mass`，该部分收益保留在 [-1,+1] 区间；不把未知结果算成真实输局，也不把条件于已结束轨迹的均值当作总收益。

计划阶段使用 `cooperative` 与 `greedy` 两种简单续局策略，二者都不是最优解。协作策略含让牌、送牌等启发式，因此模拟结果与这些设计有关系，需要接受独立对局验证。

## 评测范围

当前是 **root-action evaluation（首步动作评测）**：只有首步来自待评测方法，后续所有玩家（包括自己、队友、对手）统一使用评测策略。评测改用 `random` 与 `pressure`，同场景的三组共享隐藏分配权重和两个固定随机种子。

这用于隔离首步选择的作用，不代表三套方法在每一步持续决策的完整对局胜率。评测策略虽然不同于计划策略，但仍是简单人造策略；隐藏牌先验也相同，不能声称是独立真实世界验证。

主要报告：

- 各评测续局策略下的团队胜负质量、截断质量及奖励区间。
- 全部实验完成时各场景等权、评测策略等权后的平均团队奖励；胜 +1、负 -1。发生执行错误时汇总仅覆盖成功决策，应同时检查错误数和缺失场景。
- 单次决策耗时（模拟组含重新规划；不含共同的事后评测），API 次数和成功调用用量。
- 重复同场景时动作的众数占比，作为描述性稳定度，不计算统计显著性。
- 人工建议和全知结果放在 `diagnostics`，不影响动作选择或实验完成状态。

API/协议错误记录为 `execution_error`。合法但次优或与人工不同的动作仍是正常实验结果。错误发生前的部分 API 用量可能未计入成功决策用量，不能据此当作完整账单。

`paired_complete_comparison` 仅比较三组均成功完成的相同场景、相同重复轮次，避免某组缺失样本造成直接比较偏差。它是完整样本分析，仍须报告被排除的执行错误；若错误与困难场景有关，也不能据此推广到全部场景。

后续可扩大规则范围、加入更强且多样化的对手策略，再实现每一步重新规划的整局评测。现阶段不把这组特意构造的小残局当作泛化测试集。
