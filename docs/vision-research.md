# 图片识别输入研究

测试对象为现有内网兼容服务，实际返回 `pplx-decider-v1.1-27b`。地址仅在本机 `.env.vision`，公开代码和报告不依赖该地址。

## 数据和方法

使用 `tests/fixtures/external/opening.png` 与 `jokers.png` 两张真实截图，共 37 张人工标注的牌面，覆盖重复点数、10、字母牌、2、大小王。标签仅用于计分，不发送给模型。所有方法使用同一批角标裁图、同一端点和相同的 0.8 执行门槛；无重试挑选结果。

这两张截图是开发样本，不是大样本留出集。图片准确率与测试通过数、斗地主胜率是不同指标。

```sh
games/doudizhu/.venv/bin/python scripts/benchmark_vision.py \
  --env-file .env.vision --output games/doudizhu/runs/layout-comparison
# 控制变量：仅移除原 state 中的 image_order，其余输入保持一致
games/doudizhu/.venv/bin/python scripts/benchmark_vision.py \
  --env-file .env.vision --modes no_order --output games/doudizhu/runs/no-order-comparison
```

[逐牌结果与耗时](../reports/vision-input-layouts.json)。原始响应保存在本机被忽略的 `games/doudizhu/runs/vision-research/`。

原始请求将零起始的 `card_0` 等问题名称放进图片顺序，又在问题里使用一起始的“image 1”。移除该字段后错误消失，支持“文本序号干扰图片对应”的解释；这不是对模型内部机理的证明。原始请求在不同运行中复现了相同的跨牌替换，不能用单张识别成功替代多牌验证。

实施选择为单牌单请求：每个问题只看到一张牌，没有跨图片编号，也没有本地点数答案。在当前服务这次测量中，它比四图多问题更快；不保证所有服务都有相同速度关系。保留原置信度门槛、排序、牌堆数量、出牌历史及画面确认校验，不通过降低门槛或文本回退掩盖识别失败。

## UI 图片核对

在新种子 45 的首轮，20 张手牌经单图路径识别后进入 DouZero 决策，但原整屏 UI 请求超时。裁掉与操作无关的页面区域，保留牌桌身份、手牌、回合提示和按钮，以 1240×570 像素发送。所有目标仍使用原页面 CSS 坐标，公共输入声明裁图原点 `(100,220)`，原始截图完整留存。

另一个问题来自问题间输入隔离：`visual_check` 不会自动看到 `rank_*` 和 `button` 问题里的候选。原核对问题只知道要出哪些牌，不知道完整点击计划。现将 `proposed_click_plan` 放进公共 state，使每个问题都能读取坐标和目标。

同一张失败截图补齐公共计划后，核对置信度由约 0.70 升至约 0.88，请求约 5.9 秒完成，达到原有 0.8 门槛。该测量是一个截图案例，不能推广为所有界面的准确率或延迟。

## 依据

- [官方模型卡](https://huggingface.co/perplexity-ai/pplx-decider-v1.1-27b/blob/14c9d90137962d300f3de95633f7b6535e80c5ce/README.md)：视觉输入自动缩放；训练和公开评测上限为 512×512，默认推理图片上限更高；每个问题总上下文上限 8192 token。
- [官方 server.py](https://huggingface.co/perplexity-ai/pplx-decider-v1.1-27b/blob/14c9d90137962d300f3de95633f7b6535e80c5ce/source/src/autojev/server.py)：每个问题构造独立的 `state + question + images` 行，图片在问题间重复，不共享其他问题的候选。
- [官方 model.py](https://huggingface.co/perplexity-ai/pplx-decider-v1.1-27b/blob/14c9d90137962d300f3de95633f7b6535e80c5ce/source/src/autojev/model.py)：图片先于文本加入输入，使用 processor 预处理，再读取分类头概率。当前内网部署的源码版本未核实；以上作为公开参考实现，不冒充服务器内部证据。

按钮动作另行核对：过牌/叫分只校验按钮及回合，不要求选择手牌。新种子 45 中的一张过牌截图，在分离按钮语义并提供裁图坐标后通过 0.8 门槛；负例使用另一张非我方回合截图，模型选择 reject 且执行器拒绝执行。未降低置信门槛。

## 图片闭环实测结果

| 场景 | 结果 | 说明 |
| --- | --- | --- |
| 开发种子 45，第一次 | 首轮 UI 请求超时 | 原始整屏图片 |
| 开发种子 45，第二次 | 首轮 UI 核对低置信度停止 | 已裁图，尚未补齐公共点击计划 |
| 开发种子 45，第三次 | 确认 12 手后停止 | 过牌核对仍混入选牌要求 |
| 开发种子 45，第四次 | **整局完成，确认 27 手出牌/过牌** | 单图识牌、牌桌裁图、公共计划、独立按钮语义 |
| 未参与修正的种子 46，农民 | **未完成，点击前停止** | 手牌识别及各牌/按钮选择通过，综合核对 confidence≈0.783 未达到 0.8 |

[完整结构化结果，包含失败前缀](../reports/vision-match-research.json)。实际模型均为 `pplx-decider-v1.1-27b`。种子 45 的成功是开发回归，不是独立泛化验证；种子 46 的失败保留为未完成，不算输局，不通过换种子替代。

当前结论：多牌识别问题已在对照样本上定位并修正；一个完整的图片驱动对局已跑通，但尚未达到稳定整局运行。不能将原先的 OCR+文本 Jev 成绩计入图片模式。

后续重点是分解综合 UI 核对：回合文字、按钮标签/可用状态、每个牌张坐标分别验证；用正常、非我方回合、错牌、错按钮、遮挡和过期截图作为独立正负例，再检验整局。当前生产路径仍保留 0.8 门槛，不因本次 0.783 接近门槛就降低标准。扩大截图与未见种子覆盖后，才评价是否可以作为默认自动操作模式。

正确性检查：114 项主测试和 7 项网页测试通过；图片接口、逐牌单请求、裁图坐标转换、拒绝错误映射都有回归覆盖。这些测试不替代真实模型准确率与成功完成率。

## 独立像素核对实验（继续研究）

当前图片 UI 路径已将综合 `visual_check` 替换为独立请求：整桌图读取回合、按钮裁图读取标签、整桌图判断按钮是否启用、每张目标牌的牌角裁图读取点数。牌张请求包含全部点数候选，不提供期望点数；客户端再将识别结果与模型指定点数比较。逐请求响应保存在 `ui_mapping.checks`，包括实际模型名称。文本路径不变，0.8 门槛不变。

种子 46 原失败截图中的六张牌和按钮通过核对（各项置信度超过 0.99）。将目标位置移到错误牌张或错误按钮时，模型分别读出实际的 `3` 和 `不出`，客户端拒绝执行。另一张非我方回合截图同样停止。以上是开发截图对照，不能当作独立准确率评测。

整局回归第一次在叫分启用状态检查处停止；将启用状态的图片从单按钮裁图改为包含其他按钮的牌桌图后，第二次确认 **22 手出牌/过牌、产生 8 次策略决策**，最终在过牌按钮启用状态置信度约 **0.512** 时停止。该牌局没有完成。已知可以点击的种子 45 过牌按钮也未通过启用状态检查，说明该能力仍不稳定。

补充错位/遮挡对照时服务端返回 HTTP 529；这些请求算服务失败，不能声称识别正确或成功拒绝遮挡。尚未进行新的未见种子整局验证，也没有新增过期截图对照；执行器既有的点击前截图变化检查仍保留。

[本轮结构化记录](../reports/vision-ui-split-research.json)。116 项主测试和 7 项网页测试通过。后续应先收集启用/禁用按钮的人工标注截图，验证具体视觉样式的辨识能力，再扩大整局验证；不能把低置信度直接改为放行。

## 按钮状态像素适配与整局验证

为当前绿色牌桌增加 `external/buttons.py`：只读取按钮位置附近的截图像素，识别启用的亮米色文字/金色填充，以及禁用的暗色文字。它是明确的固定界面适配规则，不是通用视觉模型，也不将像素比例包装为置信度；未知样式拒绝。Jev 仍独立识别回合、按钮文字、目标牌点数，模型的 0.8 门槛不变。运行时不读取 DOM、CSS 属性或游戏 API。当前对不选牌的按钮动作检查启用状态；出牌按钮在选牌前可能禁用，不在该阶段要求它启用。

16 张人工核对的按钮裁图保存在 `tests/fixtures/buttons/`，包含不出、不叫、叫分按钮的启用/禁用样式；样本来自两局开发记录，有重复外观，不能作为 16 个独立泛化样本。全部分类符合标注，黑/白/红/空绿色遮挡返回未知。集成测试验证禁用按钮即使通过模拟的回合和文字识别也仍然被拒绝。

| 场景 | 结果 | 截图确认手数 |
| --- | --- | --- |
| 种子 46，固定不叫，开发回归 | 完整结束 | 37 |
| 种子 47，固定叫 3 分，未参与调试 | 完整结束 | 21 |

两局均使用图片识牌及图片 UI 核对，实际模型返回 `pplx-decider-v1.1-27b`；按钮状态由固定界面像素适配器判断，没有失败后切换为文本或本地牌面识别。保留点击前画面变化检查和点击后的可见历史确认。[结构化结果](../reports/vision-button-style-research.json)。这证明当前界面可以完成闭环，不证明跨皮肤适配、长期成功率或模型胜率。

119 项完整主测试和 7 项网页测试通过；其中 3 项按钮专项测试全部通过。换主题、分辨率或按钮设计须重新标注验证，不能沿用这些颜色阈值宣称通用识别。
