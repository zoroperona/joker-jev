# 简单斗地主 AI 与 10 场协议

`SimpleDoudizhuAgent` 继承通用 `Agent`，复用 `CardGame` 引擎；`choose_simple` 只接受玩家视角。实现是本仓库原创启发式，没有复制开源代码、不需要训练权重或外部依赖，也不调用 JEV。当前与游戏引擎一样仅支持单牌/对子/王炸受限残局。

## 决策顺序

1. 只有一个合法动作时直接执行；能直接出完时优先终局。
2. 队友掌权，且公开信息排除后续对手接牌直接出完的可能时，让牌。
3. 对手剩一张、当前跟单牌时，尝试用最大可出牌守门。
4. 自由领出且对手剩一张，优先较小对子；否则下家队友剩一张时尝试领小单张。
5. 其他情况优先降低剩余手牌在无人压制时的最少出牌次数，再保对子、节省大牌。

这些是简单、确定性的策略偏好，不是正确答案。它不知道对手真实底牌；未知牌计数和“可能接住”的推断仅来自自己的手牌与公开计数。守门、喂牌等行为可能判断失误。

## 运行

```bash
# 简单 AI 自对弈：验证运行，无网络；这个结果不是 JEV 胜率
python3 -m joker_jev.games.doudizhu.match --local --output reports/simple-selfplay-new.json

# 真实 JEV 对简单 AI，恰好 10 场
python3 -m joker_jev.games.doudizhu.match --seed 20261015 --model jev-1.13.0 --output reports/jev-vs-simple-new.json

python3 -m unittest discover -s tests -v
```

真实实验使用 `current_jev`：战术判断加 Choice，不给它模拟评分。10 副新的混合残局在任何 API 请求前固定，各结构层两副。JEV 轮流占据地主 4 场、地主下家 3 场、地主上家 3 场；另外两个座位都使用简单 AI。所以 JEV 为农民时，队友也是简单 AI。胜率指 JEV 所在团队获胜的完整对局数 / 完整对局总数，不是三位 AI 的独立胜率。

每一场从快照推进到自然终局。API 失败或回合上限记录为未完成，不当输局、不更换牌局、不自动补跑。报告保存冻结牌局及哈希、设置、逐步视角和动作、公开历史、团队收益、调用记录、已知 token、接口错误与真实模型版本。研究日志可能包含不同座位在各自回合的手牌；这些日志不传给其他玩家。

只有 10 场，身份占比不等，也不是同一发牌轮换身份的配对实验，因此不能据此作稳定实力或完整斗地主胜率结论。正确性测试验证规则、接口、信息隔离和可复现配置，不设置胜率或最优决策通过门槛。
