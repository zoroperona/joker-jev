# v3：玩家视角采样模拟

## 为什么先做这一项

`README` 的待办里，按“对胜率的预期收益 / 对速度的代价”排序：

| 待办 | 处理 | 理由 |
|---|---|---|
| 有限步隐藏牌采样与后续模拟 | **已做（v3 核心）** | v2 只给静态拆牌组数，JEV 看不到动作的实际后果；模拟直接估计每个候选的团队胜率与积分。 |
| 分开评测叫地主与出牌 | **已做（离线消融）** | 离线评测分 `rollout_play`（只改出牌）与 `rollout`（叫分也用模拟）两组。 |
| 守门/送牌/接管与身份、位置结合 | 由模拟覆盖 | 模拟按真实轮次和剩余张数打完，自然体现这些后果，不再追加固定口诀。 |
| 基于公开行为的猜牌 | 暂缓 | 收益不确定，且会让采样依赖对手模型；先用均匀采样。 |
| 更多牌局/多种对手 | 部分 | 新增免 API 的离线配对评测，可廉价跑数百局；多种对手留待后续。 |
| 响应校验与请求大小 | 顺带 | v3 只发最近 6 条历史，候选默认一次 Choice。 |

速度约束：JEV 单次调用约 0.6 s。模拟预算设为与之同量级（出牌约 0.5 s / 600 次模拟，叫分约 0.5 s / 200 次）。

## 做法

- `full/rollout.py`
  - `simple_play`：把 `FullSimpleAgent` 的出牌规则改写为纯函数；`FullSimpleAgent` 现在调用它，200 局自对弈的逐步动作与旧版逐字节一致。
  - `simulate`：不经过通用引擎（无 deepcopy/日志）的快速对局，积分公式与 `FullDoudizhuGame` 相同，测试逐局比对。每局约 2.7 ms（原先约 5 ms，主要来自 `rough_groups` 改为计数向量和缓存）。
  - `WorldSampler`：仅用自己的手牌、已出牌、各家张数和已公开底牌，把未见牌随机分给其他两家（叫分阶段另抽 3 张底牌）。随机种子只由玩家视角派生，测试保证互换对手实际手牌后结果不变。
  - `evaluate_plays`：所有候选共享同一组采样世界（降低方差），逐轮减半：先给全部候选少量样本，再把预算集中到前一半。被淘汰的候选样本更少，结果里如实给出 `samples`。
  - `evaluate_bidding`：估计“自己当地主（底牌随机）”与“他人当地主”时每 1 分叫分的平均积分和胜率。
- `SimulationJEVAgent`（`--strategy v3`，现为默认）
  - 在 v2_compact 后果之上为每个候选加 `simulation: {samples, team_win_rate, mean_score}`，候选按模拟积分排序。
  - 超过 24 个候选时给出前 23 个和一个 `more_options`，选中后再分页，所有合法动作仍可达；通常只需一次调用（v2_compact 约 9% 的决策要两次）。
  - 能立即出完时由代码直接出完（多种出完方式取积分最高者），不调用 JEV。
  - 只发送最近 6 条公开事件；完整出牌记录已在 `public.played` 中。
- `RolloutAgent`：纯代码基线，叫分/出牌都取模拟最优，用来离线验证信号。

## 离线验证（无 API）

```bash
python3 -m joker_jev.games.doudizhu.full.local_eval --games 600 --strategies simple,rollout_play,rollout --workers 16
```

同一 600 副牌、同一目标座位（轮换 p0/p1/p2），另两家均为简单 AI：

| 目标座位策略 | 胜率 | 平均积分 | 地主 胜/局 | 农民 胜/局 |
|---|---:|---:|---:|---:|
| simple（基线） | 51.8% | -0.05 | 204/343 | 107/257 |
| rollout_play（只改出牌） | **73.7%** | 2.04 | 285/343 | 157/257 |
| rollout（叫分+出牌） | 69.0% | **2.41** | 156/187 | 258/413 |

配对比较：`rollout_play` 对基线 154 局独赢 / 23 局独输，积分差 +2.08（标准误 0.28）；`rollout` 152/49，+2.45（0.30）。模拟叫分更少当地主、但当上地主时胜率 83%，积分更高，胜率反而略低——两者目标不同，按积分优化。

[原始数据](../reports/doudizhu-local-rollout-v1.json)

**限制**：模拟中所有座位都用简单 AI 打法，而实验对手正好是简单 AI，所以这是“对手模型正确”的乐观情形；换成更强或不同风格的对手，收益会下降。均匀采样不利用过牌等行为信息。

## 线上配对（JEV）

```bash
python3 -m joker_jev.games.doudizhu.full.compare_strategies --baseline v2_compact --candidate v3 --fresh-seed 20270101 --cases-per-split 10 --workers 3 --output reports/doudizhu-strategy-ab-v3.json
```

模型 `jev-1.13.0`，开发回归 10 副 + 新牌 10 副（20270101 起，首次使用），每副两版各跑一次：

| 数据集 | v2_compact 胜/完成 | v3 胜/完成 | v2_compact 平均积分 | v3 平均积分 |
|---|---:|---:|---:|---:|
| 开发回归 | 5/10 | **8/10** | -0.6 | 3.9 |
| 新牌 | 0/9 | **8/10** | -5.6 | 1.5 |

双方都完成的 19 对中，v3 独赢 11 对，v2_compact 独赢 0 对。v2_compact 有 1 局 Choice 响应校验失败，保留为未完成、不计输局；v3 无失败。

| 速度与用量 | v2_compact | v3 |
|---|---:|---:|
| 每局 API 调用 | 7.8 | 8.4（立即出完不再调用；叫分更常有多个选项） |
| 需要两次调用的决策 | 10/146 | 0/174 |
| 平均输入 token / 调用 | 4260 | 4121 |
| 每局耗时 | 7.9 s | 12.8 s |

耗时增加来自本地模拟；评测用 3 个线程并行，CPU 模拟受 GIL 争用，单局串行时增加量约为每个决策 0.5 s。JEV 在 149 次有模拟的决策里有 126 次（85%）选择了模拟排名第一的动作。

20 副牌仍是小样本，对手正是模拟所用的简单 AI；结果说明方向正确，不证明对其他对手同样有效。[配对报告](../reports/doudizhu-strategy-ab-v3.md)
